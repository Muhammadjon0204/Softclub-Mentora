# Phase 1 TZ Traceability Matrix

Матрица ограничена требованиями, релевантными Phase 1 (Organization Admin + общая инфраструктура, на которой строятся все фазы). Полная матрица без фильтра — Приложение J ТЗ; при любом сомнении Приложение J остаётся нормативным источником, эта таблица — его проекция на Phase 1 плюс Frontend-специфичные колонки.

Колонка **Классификация**: `TZ-MUST` / `PRODUCT-APPROVED EXTENSION` / `IMPLEMENTATION DETAIL` / `FUTURE PHASE` / `PRODUCT DECISION REQUIRED` / `OUT OF SCOPE`. Колонка **Текущий статус**: состояние во Frontend сегодня (`PREVIEW_ONLY` / `READY_TO_CONNECT` / `UI_MISSING` / `N/A`).

## Требования ТЗ без соответствующего UI в текущем Frontend

Для каждой строки: `Req. classification = TZ-MUST`, `Decision status = CONFIRMED`, `Backend = REQUIRED` — контракт полностью определён ТЗ и не понижается отсутствием кнопки (см. правило в начале [Phase_1_API_Endpoint_Catalog.md](./Phase_1_API_Endpoint_Catalog.md)).

| Requirement ID | Что требуется | Frontend status | Backend status | Почему нет UI | Рекомендация |
|---|---|---|---|---|---|
| `BRN-005` (make-head-office) | Кнопка смены главного офиса | UI_MISSING | REQUIRED | Не реализовано в `BranchesPage`/`BranchDetailsDrawer` | Backend реализует endpoint; UI добавить до конца Phase 1 или в начале Phase 2 |
| `ASN-025` (force-cancel) | Кнопка принудительной отмены задачи | UI_MISSING | REQUIRED | `AssignmentsPage` сделана намеренно read-only (комментарий в коде) | Backend реализует endpoint обязательно, независимо от Frontend; UI можно добавить отдельным небольшим тикетом, не блокирующим остальной Phase 1 |
| `TEN-070`/`TEN-073` (сравнение филиалов) | `GET /reports/branches` + визуализация | UI_MISSING | REQUIRED | Явного блока сравнения в `ReportsPage` не обнаружено | Backend реализует endpoint; уточнить с Product, нужен ли отдельный UI-блок в Phase 1 или это Phase 2 |
| `USER-011`…`017` (чистая смена категории) | Перевод Mentor/Lead между категориями одного филиала без смены роли | UI_MISSING | REQUIRED | Функциональность скрыта внутри диалога «Change role» | Backend реализует endpoint отдельно; вопрос об отдельной кнопке — Product Decision по UI, не по backend |
| `TG-005/006/010`, `AUTH-014` (собственный профиль) | `/profile`: смена пароля, Telegram bind/status/unbind | UI_MISSING | REQUIRED | Маршрут `/profile` отсутствует во Frontend; компонент `ChangePasswordForm` уже написан, но не смонтирован | Backend реализует endpoints; Frontend должен домонтировать `/profile` маршрут (вне scope Backend, но блокирует полноту UX) |

## UI-функции без прямого пункта ТЗ

См. полный разбор с рекомендациями в [Phase_1_Product_Extensions_and_Open_Questions.md](./Phase_1_Product_Extensions_and_Open_Questions.md): создание Branch с полями `city/email/phone` (PRODUCT-APPROVED EXTENSION) и назначением администратора «за один шаг» (оркестрация); «Block/Unblock» пользователя как отдельное действие (открытый вопрос, модель не финализирована); переключатели уведомлений/интеграций на `/admin/settings` (открытый вопрос: system/organization/deployment-level); экспорт отчётов (PRODUCT-APPROVED EXTENSION, требует обновления раздела 5 ТЗ); `notificationLanguage` в профиле пользователя.
